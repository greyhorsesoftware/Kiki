# 09 — Omarchy integration

**Status:** built; portal and FileManager1 hand-verified on the installed package; D-Bus activation not in 0.1.0.

Builds on: `01-daemon-and-listing.md` (the daemon), `02-shell-and-views.md` (the window).

Mockup: `OpenDialog.dc.html`.

## Goal

kiki is Omarchy's file manager: `xdg-open` on a folder launches it, browsers and chat apps can "Show in folder", and every app's Open and Save dialogs are kiki's.

## Design

- **Desktop entry**: `org.kiki.App.desktop` with `MimeType=inode/directory;x-scheme-handler/sftp;x-scheme-handler/ftps;` and `Exec=kiki %U`. No `x-scheme-handler/file`: `xdg-open` does not route `file:` through scheme handlers. ~~(the id must equal the bus name for D-Bus activation to work) … `DBusActivatable=true`. Install runs `xdg-mime default org.kiki.App.desktop inode/directory`.~~ **Amended 2026-09-21:** `DBusActivatable=true` is gone (D12), and the package's install hooks run as root, where `xdg-mime default` would set *root's* handler — so the package sets nothing; the first-run dialog does, per user.
- ~~**D-Bus activation**: kikid owns `org.kiki.Daemon`; `kiki` the window owns `org.kiki.App` with `Activate`, `Open(uris)`.~~ **Amended 2026-09-21: not in 0.1.0 (D12).** Nothing in kiki owns `org.kiki.App`, so a launcher that activated it would wait on a name nobody claims and lose its URIs; `org.kiki.App.service` is not installed. A second launch goes through `/usr/bin/kiki`, which finds the running instance by the path of its `shell.qml`, hands it the URI over `shell present <uri>`, and raises the window with `hyprctl dispatch focuswindow pid:…`. The daemon is reached through its socket unit, not through a bus name.
- **URIs everywhere**: the `kiki` binary accepts any URI (`kiki sftp://homelab/srv`), the desktop entry registers `x-scheme-handler/sftp` and `x-scheme-handler/ftps` so `xdg-open sftp://…` lands in kiki, and every D-Bus entry point below passes URIs straight to `open(uri)`.
- **Becoming the default (per user, reversible)**: the package only installs files under `/usr`, so kiki asks on first launch ("Make kiki your file manager?") and does the per-user work itself through `Integrate`; Settings → Omarchy is one switch. **Simplified 2026-10-06** (owner: "just one switch on/off w/ list of stuff we bind (in human terms) no file nonsense" … "yes do the dialog too"): both screens were a part-by-part affair — four checkboxes in the dialog, each with the file it wrote beneath it, and four rows of Apply/Remove on the page — and both are now one answer over one list, in the words a person would use for it (`T.omarchyDoes()`, so the two cannot drift): the two keys, folders opening in kiki, another application's Open and Save dialogs, "Show in folder", and Quick Look floating. No paths, no part names, and no way to take three of the four — a desktop with kiki on the keys but not in the dialogs is one nobody asked for. The switch reads on only when every part is in place, so a half-applied desktop cannot look finished, and what fails is named in those same words rather than by its file. The parts themselves are unchanged, and `Integrate { parts }` still takes a list for anyone driving it over the wire. The four items: (1) `inode/directory` and the `sftp`/`ftps` scheme handlers set to `org.kiki.App.desktop` in `~/.config/mimeapps.list` through `xdg-mime`, verified by reading the file back; (2) user D-Bus activation files in `~/.local/share/dbus-1/services/` for `org.freedesktop.FileManager1` and the portal backend name, which the session bus prefers over the distro's files in `/usr/share`, with `Exec=/usr/bin/kikid` and `SystemdService=kikid.service`; (3) a `-- kiki: begin … -- kiki: end` block of **Lua** in `~/.config/hypr/bindings.lua` — the file `hyprland.lua` requires and the one Omarchy tells a person to put their own bindings in — with `Super+Shift+F` (open kiki), `Super+Alt+Shift+F` (open the terminal's folder via `omarchy-cmd-terminal-cwd`) and Quick Look's float/pin rule, written atomically after a `hyprctl configerrors` preflight, reloaded, and rolled back automatically if Hyprland reports errors. **Corrected 2026-10-06** (`docs/0.5.0/12-hypr-lua.md`): until then the block was written in Hyprland's old configuration language into `~/.config/hypr/bindings.conf`, which nothing sources — `hyprctl binds` listed 228 bindings on the owner's desktop and not one of them was kiki's, so `Super+Shift+F` had never opened kiki and Quick Look had never floated. The block now unbinds the two chords before binding them, because Omarchy's defaults hold both (Nautilus), and launches through Omarchy's `o.bind(…, { launch = … })` where its helpers are loaded so kiki starts in the same uwsm scope as every other application there, falling back to Hyprland's own `hl.*` where they are not; applying or removing sweeps the dead block out of the old file. Float/center/size rules for a `kiki-chooser` window class stood in that block until 2026-10-04, when the chooser became a window of its own — and a *layer* surface, which no window rule can match: they were removed, `docs/0.5.0/11-chooser-window.md`; (4) `org.freedesktop.impl.portal.FileChooser=kiki;gtk` in `~/.config/xdg-desktop-portal/portals.conf` (existing backends kept as fallbacks, gtk last) followed by `systemctl --user restart xdg-desktop-portal`. **Settled 2026-09-21** (`CORE.md`'s open question): kiki's chooser sits *beside* GTK's, per user, with **gtk as the fallback** — it never replaces it system-wide. The package only makes the chooser available (`/usr/share/xdg-desktop-portal/portals/kiki.portal`); the system-wide `kiki-portals.conf` drop-in was dropped, since xdg-desktop-portal reads `<desktop>-portals.conf` and a file of that name is never read on Hyprland. The first apply of each item records what it replaced in `~/.config/kiki/integration.toml` (the previous `inode/directory` handler, the previous FileChooser chain, any pre-existing override file), and Remove puts those exact values back rather than merely deleting kiki's lines; a second apply never overwrites the recorded original. The Hyprland block adds lines only, and the two unbinds it needs live inside it, so stripping it is already exact: Omarchy's own bindings are simply there again. Implemented in `kikid/src/integrate.rs` with unit tests over a scratch home.
- **Show in folder**: `org.freedesktop.FileManager1` (`ShowItems`, `ShowFolders`, `ShowItemProperties`). **As built:** the interfaces are served by `kiki-plugin-dbus`, a helper the daemon spawns and bridges to (`kikid/src/dbus.rs`), not by kikid itself — zbus and its dependencies stay out of the daemon. `ShowItems` raises the window and selects the file once the folder has listed, found by the daemon rather than among the rows already loaded; `ShowItemProperties` opens the inspector.
- **Portal FileChooser**: an `org.freedesktop.impl.portal.FileChooser` backend (`OpenFile`, `SaveFile`, `SaveFiles`), with a portal config that routes FileChooser to kiki. **As built:** the same helper owns the bus name `org.freedesktop.impl.portal.desktop.kiki` and serves the interface at `/org/freedesktop/portal/desktop`; the daemon asks the running kiki to show the dialog over its IPC and the result comes back over the socket. **Amended 2026-10-04** (`docs/0.5.0/11-chooser-window.md`): the dialog was an overlay inside the kiki window, which put another application's Save behind the application that asked; it is now a surface of its own on the overlay layer (`ui/ChooserWindow.qml`), above every window and on the output the person is looking at. There is still no `parent_window` to honour — a layer surface needs none — and the `kiki-chooser` window rules are gone rather than inert, since a window rule cannot match a layer. Filters, multiple selection, directory mode, current folder and suggested name follow the portal spec. ~~Remote locations are allowed; the daemon streams the file to a temporary local path and returns that URI.~~ **Amended 2026-09-21 (D13):** Locations are hidden in the chooser rather than returning an `sftp://` URI the caller cannot open; fetching to a temp file is post-0.1.0. **The chooser sizes to the window (2026-09-21)**: 860 × 560 at most, and the window less a 24 px margin when that is smaller, with Cancel/Save held to its right edge — a fixed box was cut off in a short window (`tst_PortalPick`).
- **Trash favorite** integrates with `org.freedesktop.FileManager1`-aware apps by exposing the standard Trash directory.

## Verification

- `xdg-open ~/` opens kiki at home; `xdg-open file.txt` still opens the file's own handler.
- Firefox's "Show in folder" reveals the download selected.
- A GTK app's Open dialog and a Qt app's Save dialog are kiki's; filters and suggested names arrive correctly. ~~picking a file on the SFTP location returns a readable local URI~~ **Amended 2026-09-21:** the chooser shows no Locations (D13).
- kiki is not launched twice for two `xdg-open` calls; the second focuses the existing window.
- The chooser fits a 700 × 420 window with its buttons reachable (`tst_PortalPick`).
