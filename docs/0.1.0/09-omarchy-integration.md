# 09 — Omarchy integration

**Status:** built; portal and FileManager1 hand-verified on the installed package; D-Bus activation not in 0.1.0.

Builds on: `01-daemon-and-listing.md` (the daemon), `02-shell-and-views.md` (the window).

Mockup: `OpenDialog.dc.html`.

## Goal

kiki is Omarchy's file manager: `xdg-open` on a folder launches it, browsers and chat apps can "Show in folder", and every app's Open and Save dialogs are kiki's.

## Design

- **Desktop entry**: `org.kiki.App.desktop` with `MimeType=inode/directory;x-scheme-handler/sftp;x-scheme-handler/ftps;` and `Exec=kiki %U`. No `x-scheme-handler/file`: `xdg-open` does not route `file:` through scheme handlers. ~~(the id must equal the bus name for D-Bus activation to work) … `DBusActivatable=true`. Install runs `xdg-mime default org.kiki.App.desktop inode/directory`.~~ **Amended 2026-09-21:** `DBusActivatable=true` is gone (D12), and the package's install hooks run as root, where `xdg-mime default` would set *root's* handler — so the package sets nothing; the first-run dialog does, per user.
- ~~**D-Bus activation**: kikid owns `org.kiki.Daemon`; `kiki` the window owns `org.kiki.App` with `Activate`, `Open(uris)`.~~ **Amended 2026-09-21: not in 0.1.0 (D12).** Nothing in kiki owns `org.kiki.App`, so a launcher that activated it would wait on a name nobody claims and lose its URIs; `org.kiki.App.service` is not installed. A second launch goes through `/usr/bin/kiki`, which finds the running instance by the path of its `shell.qml`, hands it the URI over `shell present <uri>`, and raises the window with `hyprctl dispatch focuswindow pid:…`. The daemon is reached through its socket unit, not through a bus name.
- **URIs everywhere**: the `kiki` binary accepts any URI (`kiki sftp://homelab/srv`), the desktop entry registers `x-scheme-handler/sftp` and `x-scheme-handler/ftps` so `xdg-open sftp://…` lands in kiki, and every D-Bus entry point below passes URIs straight to `open(uri)`.
- **Becoming the default (per user, reversible)**: the package only installs files under `/usr`, so kiki asks on first launch ("Make kiki your file manager?", four checkboxes) and does the per-user work itself through `Integrate { parts }`; Settings → Omarchy shows each item with its file, an Apply/Remove button, and "Remove kiki from Omarchy". The four items: (1) `inode/directory` and the `sftp`/`ftps` scheme handlers set to `org.kiki.App.desktop` in `~/.config/mimeapps.list` through `xdg-mime`, verified by reading the file back; (2) user D-Bus activation files in `~/.local/share/dbus-1/services/` for `org.freedesktop.FileManager1` and the portal backend name, which the session bus prefers over the distro's files in `/usr/share`, with `Exec=/usr/bin/kikid` and `SystemdService=kikid.service`; (3) a `# kiki: begin … # kiki: end` block in `~/.config/hypr/bindings.conf` with `Super+Shift+F` (open kiki), `Super+Alt+Shift+F` (open the terminal's folder via `omarchy-cmd-terminal-cwd`) and the float/center/size rules for the `kiki-chooser` window class (inert while the chooser is an overlay inside the kiki window; they take effect once it becomes its own window with that class), written atomically after a `hyprctl configerrors` preflight, reloaded, and rolled back automatically if Hyprland reports errors; (4) `org.freedesktop.impl.portal.FileChooser=kiki;gtk` in `~/.config/xdg-desktop-portal/portals.conf` (existing backends kept as fallbacks, gtk last) followed by `systemctl --user restart xdg-desktop-portal`. **Settled 2026-09-21** (`CORE.md`'s open question): kiki's chooser sits *beside* GTK's, per user, with **gtk as the fallback** — it never replaces it system-wide. The package only makes the chooser available (`/usr/share/xdg-desktop-portal/portals/kiki.portal`); the system-wide `kiki-portals.conf` drop-in was dropped, since xdg-desktop-portal reads `<desktop>-portals.conf` and a file of that name is never read on Hyprland. The first apply of each item records what it replaced in `~/.config/kiki/integration.toml` (the previous `inode/directory` handler, the previous FileChooser chain, any pre-existing override file), and Remove puts those exact values back rather than merely deleting kiki's lines; a second apply never overwrites the recorded original. The Hyprland block only adds lines, so stripping it is already exact. Implemented in `kikid/src/integrate.rs` with unit tests over a scratch home.
- **Show in folder**: `org.freedesktop.FileManager1` (`ShowItems`, `ShowFolders`, `ShowItemProperties`). **As built:** the interfaces are served by `kiki-plugin-dbus`, a helper the daemon spawns and bridges to (`kikid/src/dbus.rs`), not by kikid itself — zbus and its dependencies stay out of the daemon. `ShowItems` raises the window and selects the file once the folder has listed, found by the daemon rather than among the rows already loaded; `ShowItemProperties` opens the inspector.
- **Portal FileChooser**: an `org.freedesktop.impl.portal.FileChooser` backend (`OpenFile`, `SaveFile`, `SaveFiles`), with a portal config that routes FileChooser to kiki. **As built:** the same helper owns the bus name `org.freedesktop.impl.portal.desktop.kiki` and serves the interface at `/org/freedesktop/portal/desktop`; the daemon asks the running kiki to show the dialog over its IPC and the result comes back over the socket. The dialog is an **overlay inside the kiki window** (`ui/PortalDialog.qml`), so there is no `parent_window` to honour and no second window to place — the Hyprland rules for the `kiki-chooser` class stay inert. Filters, multiple selection, directory mode, current folder and suggested name follow the portal spec. ~~Remote locations are allowed; the daemon streams the file to a temporary local path and returns that URI.~~ **Amended 2026-09-21 (D13):** Locations are hidden in the chooser rather than returning an `sftp://` URI the caller cannot open; fetching to a temp file is post-0.1.0. **The chooser sizes to the window (2026-09-21)**: 860 × 560 at most, and the window less a 24 px margin when that is smaller, with Cancel/Save held to its right edge — a fixed box was cut off in a short window (`tst_PortalPick`).
- **Trash favorite** integrates with `org.freedesktop.FileManager1`-aware apps by exposing the standard Trash directory.

## Verification

- `xdg-open ~/` opens kiki at home; `xdg-open file.txt` still opens the file's own handler.
- Firefox's "Show in folder" reveals the download selected.
- A GTK app's Open dialog and a Qt app's Save dialog are kiki's; filters and suggested names arrive correctly. ~~picking a file on the SFTP location returns a readable local URI~~ **Amended 2026-09-21:** the chooser shows no Locations (D13).
- kiki is not launched twice for two `xdg-open` calls; the second focuses the existing window.
- The chooser fits a 700 × 420 window with its buttons reachable (`tst_PortalPick`).
